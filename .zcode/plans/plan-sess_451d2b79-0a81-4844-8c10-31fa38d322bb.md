## 背景

用户确认：将 **drive 的 app-api 同源嵌入 agents 网关**（与 IAM 嵌入同一模式），使 `/app/v3/api/assets*` 在 agents 端口（8095/3901）可用；数据库**共用 SDKWORK_DATABASE_URL**（同一 PG 实例，drive 表 `dr_*` 由 `connect_postgres_database_and_install_schema` 幂等安装）。

已验证的关键事实：
- drive 提供公开嵌入入口：`sdkwork_api_drive_assembly::assemble_app_api_contribution()`（返回 `ApiAssemblyContribution`，含 raw business router + route manifest + drive context injector + readiness）与 `sdkwork_routes_drive_app_api::wrap_router_with_iam_web_framework(resolver, router)`（带 IAM resolver 的 Web Framework 层，不挂 `/healthz` 等 infra 路由，避免与 agents 网关的 kernel 操作路由冲突）。
- `sdkwork-iam-web-adapter` 已在 agents workspace 依赖（agents-http-shared 已用 `iam_web_request_context_resolver_from_env`）。
- drive 表无专属 schema（`CREATE TABLE IF NOT EXISTS dr_*`），共用 SDKWORK_DATABASE_URL 可行；`ensure_production_download_token_signing_configured` 仅生产 profile 校验，开发环境放行。
- 路由无冲突：`/app/v3/api/assets*`（drive）与 `/app/v3/api/ai/*`（agents）、`/app/v3/api/auth/*`（IAM）前缀互斥。
- IAM 嵌入先例（`src/bootstrap/iam.rs` → `wire_iam_app_router`）可直接照搬结构。

## 实施内容

### 1. 根 `Cargo.toml`
`[workspace.dependencies]` 新增（`sdkwork-iam-web-adapter` 已存在，复用）：
```toml
sdkwork-api-drive-assembly = { path = "../sdkwork-drive/crates/sdkwork-api-drive-assembly" }
sdkwork-routes-drive-app-api = { path = "../sdkwork-drive/crates/sdkwork-routes-drive-app-api" }
```

### 2. `crates/sdkwork-api-agents-assembly`
- `Cargo.toml`：新增 `sdkwork-api-drive-assembly`、`sdkwork-routes-drive-app-api`、`sdkwork-iam-web-adapter`（均 `workspace = true`）。
- 新增 `src/bootstrap/drive.rs`（对齐 `bootstrap/iam.rs` 结构）：
  ```rust
  pub(super) async fn wire_drive_app_router() -> Result<Router, String> {
      let contribution = sdkwork_api_drive_assembly::assemble_app_api_contribution().await?;
      let resolver = sdkwork_iam_web_adapter::iam_web_request_context_resolver_from_env().await;
      Ok(sdkwork_routes_drive_app_api::wrap_router_with_iam_web_framework(
          resolver, contribution.router,
      ))
  }
  ```
- `src/bootstrap.rs`：`assemble_api_router` 中改为 `agents_router.merge(iam_router).merge(drive_router)`（CORS layer 保持在外层）。
- `specs/component.spec.json`：`contracts.dependencyApiSurfaces` 增加 drive 条目：
  ```json
  { "workspace": "sdkwork-drive", "sdkFamily": "sdkwork-drive-app-sdk", "apiAuthority": "drive-app-api",
    "surface": "app-api", "apiPrefix": "/app/v3/api", "runtimeMode": "same-origin-mounted",
    "cargoDependency": "sdkwork-api-drive-assembly",
    "embeddedExecutableExport": "sdkwork_api_drive_assembly::assemble_app_api_contribution",
    "profileCoverage": ["standalone"],
    "coverageEvidence": ["src/bootstrap.rs#assemble_api_router", "src/bootstrap/drive.rs#wire_drive_app_router"] }
  ```

### 3. `crates/sdkwork-api-agents-standalone-gateway/specs/component.spec.json`
`dependencyApiSurfaces` 增加 drive 条目（`cargoDependency: "sdkwork-api-agents-assembly"`，`embeddedExecutableExport: "sdkwork_api_agents_assembly::assemble_api_router"`，`profileCoverage: ["standalone"]`，`coverageEvidence` 指向 `../sdkwork-api-agents-assembly/src/bootstrap/drive.rs#wire_drive_app_router`）。

### 4. 部署配置与前端 env（仅 standalone 模式；cloud 模式走统一网关，不改）
- `etc/topology/standalone.development.env`：`VITE_SDKWORK_AGENTS_PC_DRIVE_APP_API_BASE_URL` 改为 `http://127.0.0.1:8095/app/v3/api`（资产 API 走 agents 网关同源入口）；`SDKWORK_DRIVE_PUBLIC_BASE_URL` 保持默认（开发可用）。
- `apps/sdkwork-agents-pc/.env.standalone.*`（4 个）：`VITE_SDKWORK_AGENTS_PC_DRIVE_APP_API_BASE_URL` 同步指向 agents 网关（8095 或 `agents.standalone.*.invalid/app/v3/api`）。
- `apps/sdkwork-agents-pc/.env.example`：更新 DRIVE base URL 注释（standalone 模式由 agents 网关同源提供，不再需要直连 3900）。
- 数据库：agents dev 脚本已有 `ensurePostgresDevDatabaseReady`（SDKWORK_DATABASE_URL 保证）；drive schema 由嵌入时 `connect_postgres_database_and_install_schema` 幂等安装。如需显式声明，在 `standalone.development.env` 注释说明共用 `SDKWORK_DATABASE_URL`。

### 5. 明确不做
- 不改 drive 仓库（嵌入入口已公开可用）。
- 不改 cloud 模式 env / cloud gateway（平台侧已有 contribution 消费体系）。
- 不改前端 UI 能力（上一轮已完成的 AssetsService/AssetsView 修改保留）。
- 不在 agents 复制 drive 路由常量（依赖路由保持归属，积木架构 §7）。
