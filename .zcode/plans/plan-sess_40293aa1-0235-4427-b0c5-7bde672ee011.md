# Tool 管理/Admin + Drive 资产保存 设计方案

## 已确认决策
- 保存路径：**服务端保存为主**（agent 服务端集成 drive uploader service；前端也可直接调已挂载的 drive uploader 端点）
- 配置作用域：**tenant 级**（`ai_agent_tool_configuration` 表带 tenant_id）
- 资产登记：**agents 引用表（`ai_agent_item_drive_ref`）+ drive 资产中心双入口**（`/app/v3/api/assets*` 已在 agents assembly 挂载，共享 `SDKWORK_DATABASE_URL`）

## 探索结论（已确认的架构事实）
- agents assembly 已挂载完整 Drive App API（`/app/v3/api/assets*` 资产中心、`/app/v3/api/drive/uploader/*` 上传端点）→ 统一资产入口天然存在，前端保存通道现成
- drive 侧服务端保存链路：`DriveUploaderService<SqlUploaderStore>::upload_bytes(object_store, UploadBytesCommand)`，object store 由 `DriveObjectStoreRuntime::new(pool).resolve(provider_id, version)` 解析 —— 均只需 PgPool（agents 已有，SDKWORK_DATABASE_URL 共享）
- 布局约定（对齐 sdkwork-assets-ingestion-drive）：`UploaderTarget::AiGeneratedSpace` + `UploaderRetention::LongTerm` + profile 按 media kind
- 六层持久化模式（Record → ports trait → SqlAgentRepository facade → SQL 常量 → SyncPostgresAdapter → DDL+table-registry）与路由模式（http.rs handler + OpenAPI YAML 驱动 manifest）已确认

## 实施内容

### 1. 新表 `ai_agent_tool_configuration`（tenant 级工具配置）
- 字段：id, tenant_id, organization_id, tool_id, enabled(bool 默认 true), save_to_drive_default(bool 默认 false), default_arguments(JSONB), version, created_by/updated_by, created_at/updated_at, deleted_at
- UNIQUE (tenant_id, tool_id)；DDL 加入 `0001_agents_baseline.sql` + `table-registry.json`（profile: tenant_entity）

### 2. 六层持久化（遵循现有模式）
- `domain.rs`：`AgentToolConfigurationRecord`
- `ports.rs`：`AgentRepository` 增加 `get_tool_configuration` / `upsert_tool_configuration` / `list_tool_configurations`
- `persistence.rs` + `persistence/sql.rs`：Row + SQL 常量 + SyncPostgresAdapter 实现（UPSERT ON CONFLICT）

### 3. 服务端 Drive 保存（service 内新模块 `drive_asset_saver.rs`）
- 新增依赖：`sdkwork-drive-uploader-service`、`sdkwork-drive-object-runtime`（path，根 workspace.dependencies）、`reqwest`（fetch 生成 URL 字节）
- `DriveAssetSaver::save_media_resource(resource, context) -> DriveAssetRef`：
  fetch URL → `UploadBytesCommand`（AiGeneratedSpace + LongTerm + profile by kind + app_resource_id=generation id）→ `upload_bytes` → `drive://spaces/{space_id}/nodes/{node_id}` + node_id
- 构造：`DriveUploaderService::new(SqlUploaderStore::new(pool))` + `DriveObjectStoreRuntime::new(pool)`

### 4. Tool 调用管线增强（`tool_invocation.rs`）
- `MediaToolInvocationRequest { call, auth_token, save_to_drive: Option<bool> }`
- 流程：读 tenant 配置 → **enabled=false 拒绝** → save_to_drive 参数或配置默认值合并 → registry.invoke → 若 saveToDrive 且结果含 MediaResource URL → DriveAssetSaver 保存 → 结果附 drive 引用（MediaResource source=drive）
- 保存成功后写 `ai_agent_item_drive_ref`（role=GeneratedOutput/Artifact，复用现有 insert 链路，无 item 时支持独立登记）

### 5. HTTP API（http.rs + OpenAPI YAML）
- **app-api**（用户面）：
  - `GET /app/v3/api/ai/tools` — 工具目录（分类+工具+租户配置生效状态）
  - `POST /app/v3/api/ai/tools/{toolId}/invoke` — body { arguments, saveToDrive? }；auth_token 从 Bearer 提取透传 cloudrouter；返回 MediaResource（含 drive 引用）
  - `GET /app/v3/api/ai/assets` — 该租户/用户生成保存的资产列表（来自 ai_agent_item_drive_ref）
- **backend-api**（admin 面）：
  - `GET /backend/v3/api/ai/tools` — 全量工具+配置
  - `PUT /backend/v3/api/ai/tools/{toolId}/configuration` — 更新 enabled/saveToDriveDefault/defaultArguments
- 同步更新 `agents-app-api.openapi.yaml`、`agents-backend-api.openapi.yaml`（build.rs 自动生成 manifest，含鉴权等级）

### 6. 验证
- 配置 CRUD 单元测试（内存 repo）+ registry 组合测试（enabled 拒绝、saveToDrive 合并）
- DriveAssetSaver 测试（fake object store / mock fetch，不连真实网关）
- HTTP handler 测试（http_axum_contracts 模式）+ OpenAPI manifest 生成验证
- `cargo check/test` workspace 全绿；遵循 CODE_STYLE/NAMING/RUST_CODE/DATABASE_SPEC
